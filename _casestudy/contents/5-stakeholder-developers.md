## Stakeholder 2: Developers
### Speaking from Personal Experience
As a developer myself, this is a stakeholder for which I can speak anecdotally. In fact, I have and very likely will go on to doing research that involves artificial intelligence, and open sourceness will be very important for my work. The only reason I or any other independent or academic developer has been able to contribute to AI research is open source frameworks. Much of AI, including in the industry, is run with PyTorch now, and the PyTorch foundation uses the open source BSD 3-Clause licence for their library. This means that when researchers share there methods, even if there is no source code, only one implementation is required for the entire developer community to use it. I worked on a project that used graph neural networks to reason about SMT queries, and we were able to work with state of the art graph attention layers because their implementation is freely available. I would not have been able to participate in that part of the project otherwise!

### Impact on Early Developers
Similarly, open sourse software has been hugely beneficial for the inclusivity of software development everywhere. An example that I love is Godot. Many computer scientists begin their journey as young children because they want to learn how to make video games, and, while powerful, free software like Unity or Unreal Engine exists, it is bloated and difficult to use for beginners, there are less resources available for getting help, and it is not something that can be easily contributed to. With the Godot foundation's introduction of Godot 4, video game development is fully democratized: this is an engine that is more intuitive to use by independent developers because it was built by the same, and it benefits from rapid introduction of optional features from its own passionate user base. There is also a natural way for users to get into real software development: they run into a simple feature requirement the engine lacks, and they learn how to contribute to the project in order to incorporate that feature according to their vision. This is a fantastic experience for a young developer to have! All in all, having a powerful open source version of a particular kind of software available encourages healthy, long-term growth in not only that specific field, but also computer science as a whole.

Artificial intelligence is another area that I believe is appealing to inexperienced developers. Of course, purchasing hardware will always cost money, but the more open and available model training code is, the more opportunity early developers will have to solve their own problems with machine learning. 

### Making Industry-Relevant Experience More Available
These days, every software engineering job listing at a major tech or tech-adjacent company will describe the ways they are incorporating AI workflows into their development process. Just last week, I was frustrated to see that Mayo Clinic was looking for entry level employees with years of experience with specific, expensive AI tools. AI may be free to use for consumers in general, but industry-standard development tools usually cost money that I don't want to spend just so I can check a box. It's the same situation as cloud computing: by moving the majority of software infrastructure to Amazon, Azure, or GCP's servers, companies make it more difficult for fresh graduates to meet their expectations of experience. Unlike cloud computing, free access to AI tools is possible if free, state of the art models can be used for the introduction of free development tools. That would make it easier for these tools to be incorporated into curriculums as well. Personally, I hope this future comes to pass, even if I won't be able to take advantage of it.
